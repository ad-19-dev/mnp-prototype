# MNP prototype：團隊版（發送空間）

以雙語版為基礎，加上「發送空間」：每則訊息、每個收件群組、每個模板都只屬於一個空間。
規則寫在 `src/lib/teams.ts`，建立與設定團隊（同一個對話框）在 `src/components/TeamPanels.tsx`，
側欄、空間標題與分頁在 `src/components/shell.tsx`。

| 決策 | 這一版的做法 |
|---|---|
| 個人發送空間（My sending space） | 系統預設建立，只有自己看得到。適合測試和發送個人通知 |
| 共享發送空間（Shared spaces） | 每個團隊一個。訊息、收件群組、模板都屬於團隊，建立者離職也不會遺失 |
| 導覽 | 側欄：個人發送空間，以及「共享發送空間」分組底下的各團隊；「＋」建立團隊 |
| 空間內 | 標題與說明，下方分頁：訊息／收件群組／模板 |
| 成員權限 | 加入團隊一次，就能使用、編輯團隊的所有群組、模板，並查看、發送、取消團隊的訊息 |
| 團隊成員 | 沒有管理員，像聊天群組：每個人都能加入、移除成員，也能自行離開 |
| 離開團隊 | 看不到整個共享空間，包括自己建立的內容；最後一人離開時團隊與其內容一起刪除 |
| 跨空間 | 發訊息時只能選同一個空間的模板與群組；不再有「分享給個人／組織」 |
| 團隊設定 | 「新訊息」（或新增群組、新增模板）右邊的齒輪 |
| 訊息狀態 | 待核准、排程已過期、已駁回、已排程、傳送中、已送出、傳送錯誤 |
| 送審 | 需要核准的訊息送出後列為「待核准」；核准時已過排程時間就變成「排程已過期」，可立即傳送、重新排程（不需重新送審）或刪除；駁回後可修改再送審 |
| 訊息內容 | 第二步先選「新訊息」或「使用模板」（下拉選單）；Device Notifications 和 Desktop OS 各寫各的，桌面通知限 40 字標題、120 字內文，所以不會被截斷 |
| 預覽 | 第三步用 DS 樣式的簡單卡片預覽各通道，不畫擬真裝置 |
| 訊息詳情 | 方案 D：「送達狀況」先看全部通道都沒收到的人數；「各通道」每個通道一列（送達數、未送達數），展開看該通道的內容和未送達的人，並標出他們是否已由其他通道收到 |
| 列表欄位 | Sender、Channels、Title / Content、Status、Template、Reach / Audience、Created、Scheduled、Created by |

執行方式與雙語版相同：`npm install --legacy-peer-deps` 後 `npm run dev`。
